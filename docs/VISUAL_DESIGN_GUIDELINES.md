# FoxSkinServer 美术风格与设计规范

## 1. 适用范围

本文档根据 `img/` 目录中的 8 张界面截图整理，用于约束前端页面、组件、图标、插图和运营内容的视觉表现。

目标是保持一套统一的 Minecraft 社群门户视觉：以方块世界作为沉浸式背景，以深色工具型界面承载服务器、活动、项目、Wiki、公告和用户中心等信息。

## 2. 风格定位

### 2.1 核心关键词

- Minecraft 方块世界
- 深色、克制、硬朗
- 像素化细节
- 社群门户与运营后台
- 沉浸式背景与高可读信息层
- 轻量的复古游戏界面感

### 2.2 视觉原则

1. **背景负责氛围，界面负责信息。** 背景可以有雾气、光影和丰富细节，但必须退到文字和操作之后。
2. **信息优先于装饰。** 页面首先要便于扫描、比较和操作，不使用无功能的装饰性大面积元素。
3. **方正边界优先。** 通过直角面板、细边框和分隔线建立层级，不依赖大圆角和柔和阴影。
4. **颜色服务于状态。** 绿色、蓝色、金黄等颜色用于表达操作或状态，不作为大面积背景色滥用。
5. **像素元素点到为止。** 小型方块图标、工具图标和物品图标强化主题，正文与复杂信息仍以清晰易读为先。

## 3. 色彩规范

以下颜色为基于现有截图的近似设计令牌，可在实现时作为默认值，再根据实际页面对比度微调。

### 3.1 基础色

| 用途 | 建议颜色 | 说明 |
| --- | --- | --- |
| 页面底色 | `#080C0A` | 顶部导航和最深层背景 |
| 主面板 | `#0D120F` | 内容区域的主要承载色 |
| 次级面板 | `#141A16` | 输入区、选中项、局部强调区域 |
| 面板边框 | `#050705` | 建立清晰的硬边界 |
| 分隔线 | `#283129` | 低对比度横线或列表分隔 |
| 主文字 | `#E8ECE5` | 标题、主要内容和关键操作 |
| 次级文字 | `#AAB4A8` | 说明、日期、作者和辅助信息 |
| 弱化文字 | `#748077` | 不活跃、已结束或次要状态 |

### 3.2 强调色

| 用途 | 建议颜色 | 使用场景 |
| --- | --- | --- |
| 主操作绿 | `#769D4C` | 提交、进入、确认、已选中状态 |
| 链接亮绿 | `#A9D36A` | 链接、积极反馈、可点击文本 |
| 信息蓝 | `#73B5E8` | 提示、进行中、说明型状态 |
| 警示金黄 | `#D5A936` | 置顶、评估、报名、重要提醒 |
| 错误红 | `#C55A4A` | 错误、不可用或危险操作，谨慎使用 |

### 3.3 使用要求

- 页面整体应以深色中性色为主，强调色只占小面积。
- 文本和背景需要保持足够对比度；弱化文字不能用于核心操作或重要告警。
- 绿色表示正向、可操作或已完成，但不能同时承担所有状态语义。
- 蓝色、金黄和红色要保持语义稳定，避免同一颜色在不同页面表达相反状态。
- 不使用大面积紫色渐变、霓虹光晕、玻璃拟态或高亮描边作为主视觉。

## 4. 背景与图片规范

### 4.1 页面背景

- 使用 Minecraft 方块世界风景图作为页面级背景，优先选择森林、河流、村庄、山地或建筑群等具有空间层次的场景。
- 背景图覆盖可视区域，采用 `cover` 方式适配不同屏幕比例。
- 在背景上增加深色遮罩，建议使用半透明近黑色，保证面板外的导航、空白区和滚动区域仍然可读。
- 背景不应包含过亮的高光区域直接落在正文后方；必要时使用局部遮罩或降低背景饱和度。
- 页面滚动时背景保持稳定，避免背景跟随内容产生明显跳动。

### 4.2 活动与项目图片

- 活动、项目卡片使用横向图片，图片区与文字信息区上下分层。
- 图片优先展示实际 Minecraft 场景、建筑、角色、道具或活动内容，不使用无关的抽象纹理。
- 可以保留日落、暖光、雪景、星空等高氛围画面，用于区分内容类型并形成视觉焦点。
- 图片使用统一比例和裁切规则，避免同一网格中卡片高度因图片尺寸变化而跳动。
- 图片下方的文字区域保持深色，与页面面板风格一致。

### 4.3 图片质量

- 当前参考截图主要为桌面端页面，常见画布约为 `2549 × 1473`，内容区域应适配宽屏并兼容较窄视口。
- 设计稿或运营素材应同时检查桌面端和移动端裁切效果。
- 不使用过度模糊、过暗或无法识别主体的图片作为内容封面。

## 5. 排版规范

### 5.1 字体气质

- 标题和导航可以使用带像素感或游戏感的中文字体，强化 Minecraft 主题。
- 正文、表单和密集列表优先保证清晰度，不使用装饰性过强的字体。
- 中英文、数字和地址信息需要保持基线和字重协调，避免英文显得过细或过亮。

### 5.2 层级

- 页面主标题：高对比、明显大于正文，通常与页面图标位于同一行。
- 模块标题：清晰区分板块，但不能使用英雄区级别的大字号。
- 卡片标题：用于快速扫描，保持中等字重和稳定行高。
- 正文说明：使用浅灰或灰绿色，行高应足以支持连续阅读。
- 元信息：日期、负责人、分类等使用弱化色，字号小于正文但不能小到难以辨认。

### 5.3 文案与状态

- 状态标签使用简短词语，例如“进行中”“已完成”“暂停”“待复核”。
- 重要信息优先通过位置、标题和结构表达，再使用颜色补充含义。
- 链接使用绿色或下划线等稳定提示，悬停时增加亮度或边框反馈。

## 6. 布局规范

### 6.1 页面骨架

- 顶部使用固定高度的深色导航栏，包含品牌、主导航和登录/用户入口。
- 主体内容采用居中容器，容器宽度保持稳定，左右留出足够的背景呼吸空间。
- 页面标题区通常包含：主题图标、标题、简短说明以及右侧的主要操作入口。
- 页脚保持低调，使用低对比度文字，不抢占主要内容注意力。

### 6.2 栅格与信息密度

- 文字型页面可采用主内容区加侧栏的两栏结构。
- 活动和项目页面使用 2 至 3 列卡片网格；窄屏时降为单列。
- 服务列表、公告和 Wiki 索引适合采用连续列表，通过分隔线和状态列提升扫描效率。
- 组件宽度和高度应稳定，避免悬停、标签变化或文字换行导致整体布局跳动。
- 移动端优先保证标题、状态、主要操作和关键字段可见，再压缩次级说明。

### 6.3 间距

- 页面和主面板之间使用较宽外边距，形成背景与内容的层次。
- 面板内部采用一致的内边距，标题、说明和列表之间保持明确节奏。
- 列表项之间使用细分隔线和中等垂直间距，不使用过大的卡片留白。
- 建议以 `4px` 为基础单位，常用间距使用 `8px`、`12px`、`16px`、`24px` 和 `32px`。

## 7. 组件规范

### 7.1 导航

- 导航栏使用近黑背景和细底边框。
- 当前页面通过亮色文字与短下划线或底部标记体现。
- 导航项之间保持紧凑距离，避免宽大的胶囊式菜单。
- 外部链接使用明确的外链标识。

### 7.2 面板与卡片

- 默认使用直角或极小圆角，建议不超过 `2px`；除非已有组件体系另有规定。
- 面板使用近黑填充、硬边框和轻微透明度，保持与背景的区分。
- 不在卡片内部继续堆叠多层装饰卡片；需要分区时使用分隔线、标题和留白。
- 卡片标题、状态、正文、元信息应按照固定顺序排列。

### 7.3 标签与状态

- 标签采用小字号、细边框、短文本和状态色方块或文字。
- 状态色只做辅助，不单独承担信息含义。
- 已完成、进行中、暂停、不可用等状态在全站保持相同颜色和文案规则。

### 7.4 按钮

- 主要按钮使用绿色填充、深色文字或高对比浅色文字，突出提交和确认操作。
- 次要按钮使用灰色填充或透明底加边框。
- 危险操作使用红色，但需要配合明确文案和二次确认。
- 按钮高度、内边距和文字基线保持稳定，不能因图标或文字变化导致尺寸跳动。
- 工具型按钮优先使用熟悉图标；不使用带长文本的圆角按钮代替常见图标操作。

### 7.5 表单

- 输入框使用深色填充、清晰边框和高对比聚焦态。
- 字段标题、帮助文本、错误提示保持固定层级，错误提示不覆盖或挤压相邻字段。
- 复选框、下拉框和文本域沿用统一的深色边框与绿色聚焦态。
- 提交按钮通常横向铺满表单主要内容区，作为单一明确的主操作。

### 7.6 图标

- 优先使用像素化的 Minecraft 物品、方块、工具和主题符号。
- 图标尺寸保持稳定，建议在列表中使用 `16px` 至 `24px` 的视觉尺寸。
- 图标与文字基线对齐，不能因透明边缘或不同素材画布造成视觉偏移。
- 同一类信息使用同一图标，不随页面随意更换图形语义。

## 8. 交互与动效

- 交互反馈以颜色、边框、明暗和下划线变化为主。
- 动效保持短促克制，只用于页面切换、展开收起、加载或状态变化。
- 不使用持续闪烁、强烈霓虹、复杂粒子或大幅缩放作为常态反馈。
- 悬停态必须保持文字可读，不得因背景变亮而降低对比度。
- 加载、空状态、错误和提交成功状态都需要有明确的结构化反馈。

## 9. 响应式要求

- 桌面端保持居中内容区、多栏布局和背景沉浸感。
- 平板端减少侧栏宽度和卡片列数，确保主要操作仍位于首屏可见范围。
- 移动端将多栏内容改为单列，导航允许折叠或横向滚动，但不能遮挡标题和主要操作。
- 卡片图片使用稳定的宽高比；文字超长时换行，不通过缩小到难以阅读的字号解决。
- 所有固定格式控件、图标按钮、状态标签和列表行都要有稳定尺寸，避免内容变化造成布局抖动。

## 10. 禁止事项

- 不使用大面积纯黑且没有边界层级的页面。
- 不让高亮背景图片直接干扰正文阅读。
- 不将所有按钮、标签和卡片设计成圆角胶囊。
- 不大量使用紫色/蓝紫渐变、霓虹光效、玻璃拟态或装饰性光球。
- 不用抽象、模糊或与内容无关的图片替代实际 Minecraft 场景。
- 不让状态仅依赖颜色表达；需要同时提供文字、图标或结构提示。
- 不为视觉效果牺牲表单、列表和密集信息的可读性。

## 11. 设计验收清单

- [ ] 页面第一眼能识别出 Minecraft 社群门户属性。
- [ ] 背景有氛围，但不会影响导航、标题和正文阅读。
- [ ] 页面主色为深色中性色，强调色仅用于状态和操作。
- [ ] 面板、列表、卡片和表单边界清晰，信息层级明确。
- [ ] 标题、正文、辅助信息和状态标签具有稳定的字号、颜色和间距层级。
- [ ] 主要操作在桌面端和移动端都容易找到。
- [ ] 活动和项目图片主体清晰，裁切比例统一。
- [ ] 同一状态在不同页面使用相同颜色、图标和文案。
- [ ] 长标题、长链接和异常数据不会造成遮挡或布局跳动。
- [ ] 页面没有无功能的大面积装饰、强烈霓虹或过度渐变。
